# 独立验证与Spur集成的区别

2026-11-09。本文只记录当前源码可见的集成路径，尚未实施主工程修改。

本轮由当前AI Coding Agent提炼15条用户模拟记录的叙事，OpenMontage负责documentary-montage流水线、schema/checkpoint、来源适配器及VideoCompose→Remotion CinematicRenderer渲染。不是调用一个“输入所有文本就自动输出成片”的现成OpenMontage HTTP API。

现有Spur位置：

- `V2/agent/tools/video-generation/index.cjs`：DSH视频工具注册。
- `V2/agent/tools/video-generation/jobs.cjs`：持久化job、公有响应与后台worker；现实现绑定远端生成服务的requestId轮询，不能原封不动拿来执行本地OpenMontage渲染。
- `V2/web/server.mjs`：按配置注册工具，返回videoJobs和文件流。
- `V2/web/src/VideoTask.tsx`：任务轮询、播放、下载。

最小可行下一阶段：新增专用OpenMontage Adapter及渲染worker，在既有job中明确provider，统一输出id/status/url；提交只返回queued，后台依次处理脚本/素材/配音/合成/校验，完成后沿用现有视频文件接口和卡片。不能让现有远端轮询worker把本地渲染job错误发送给远端API。

用户只提交需求和授权可用记录，不需要编辑器或逐阶段审批。每个job固定所属访客和输入记录引用；只允许操作自己输出目录，失败需保留原始日志和阶段状态。进度只从真实阶段结果更新，不能做模拟百分比。

资源关键点：现有guest网关两个并发只控制DSH任务。DSH提交视频job后可能很快结束，因此不能认为它同时限制后台渲染。渲染需要独立并发池，初期可设1，任务持久排队；模型任务与渲染任务生命周期分别追踪。

本轮未验证：Spur工具触发、网页在线播放、手机播放、ECS镜像、Linux配音替代、生产多租户视频隔离、服务器资源峰值。不能把独立MP4成功当成这些项目通过。
