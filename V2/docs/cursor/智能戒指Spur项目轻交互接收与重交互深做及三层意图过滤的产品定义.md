这份说明记录 Spur 在轻交互和重交互之间的产品定义，用来分开戒指入口和 App 深区，不把两条路径合成同一种操作。

戒指上的念头要先过三层过滤，不能句句都变成任务。以一百条念头为例：大约三十条没有后续价值，仍然安静归档，不提醒、不占首页；大约四十条只是原始想法，留在录音记录里，供以后回看和纠正；大约三十条信息足够、方向清楚，才进入可执行的待办。归档不是丢弃，原始想法也不是任务。只有第三层才要求用户推进。

Spur 的轻交互是：戒指只负责接收，App 只负责推进。走路、拍摄、交谈时随口说一句，成本接近零，所以碎意图可以先全部接住。用户不必为了记下一条念头而解锁手机、找到项目、再把上下文重说一遍。接收和推进分开之后，说出来本身就算完成了入口；后面要不要做成待办，由过滤结果和 App 里的确认决定。对外动作仍然要授权，允许不等于已经完成。

这和 MetaMuse 一类重交互不同。重交互假定用户已经决定坐下来做深工作：打开 App，进入完整任务，阅读、比较、修改、授权。那条路径适合研究报告、脚本、邮件和付款，不适合每一句碎片。如果戒指也要求同样的注意力，入口成本会回到手机，轻交互就没有意义。重交互看重一次把一件事做完；轻交互看重先接住，再决定哪些值得做完。

产品边界因此写成：戒指是入口，App 是深区，不必强行合成一个界面。入口追求接得住、滤得清、打扰少；深区追求一件事讲完，该授权的停住，该完成的给出结果。一百条念头里，三十条待办进入 App，四十条原话留在记录，三十条无用内容只归档。三层可以共用记忆，但呈现密度不同。轻交互不代替深做，重交互也不接管随口一说。

过滤要靠内容，不靠说话时长。一句短话可以是待办，一段长话也可以只是想法。想法留在记录里，决定不等于已经授权，承诺才进入待办。无用内容归档后仍可找回，只是不推到今天要处理的队列。这样首页只看见大约三成可推进的事，另外七成不被做成提醒。

深区里的形态也可以有轻有重。脚本好了可以是一句话；要不要今晚继续，是当场两个选择；待办是紧凑的几行；研究进行中只显示阶段；报告用封面和摘要。这些都在 App 里推进，不要求用户回到戒指上重说。戒指不再追问细节，App 也不把每一条归档念出来。两边各做自己的事，合在一起才是从随口一说到可执行结果。入口保持轻，深区保持完整，这个分界就是 Spur 和重交互产品的差别。

轻交互交付的是结果，重交互交付的是过程。Spur 的 Agent 跑完搜索、分析、起草之后，把结论放在工作区里，用户打开就看得到，不需要从头跟一遍。MetaMuse 的用户要在界面里一步步点，每一步都是它的产品。所以 Spur 的成功标准不是功能多，而是用户说完话之后，回来看到的东西是不是已经能用。

验收看两件事：用户从说完话到看到可用结果要多久，以及要不要再做额外操作才能用上这个结果。时间短、打开就能用，才算轻交互交付了结果；如果还要从头点一遍过程，就还停在重交互。
