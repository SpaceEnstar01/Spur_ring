# 疑难杂症解决方案

## 1. Android Studio 编译时找不到 Node

### 错误

```text
A problem occurred starting process 'command 'node''
Cannot run program "node": No such file or directory
```

### 原因

Android Studio 从 macOS 图形界面启动，未获得 Homebrew Node 的 `PATH`。这不是业务代码错误。

### 解决

完全退出 Android Studio，然后在终端执行：

```bash
launchctl setenv PATH "/opt/homebrew/opt/node@20/bin:/opt/homebrew/bin:/usr/local/bin:/usr/bin:/bin:/usr/sbin:/sbin"

cd /Users/spur/X/space/claudeV2/app_front/app_yanqiang_voice/android
export PATH="/opt/homebrew/opt/node@20/bin:$PATH"
./gradlew --stop
```

重新打开 Android Studio，再执行 Sync 或 Run。

### 验证

在 Android Studio Terminal 中执行：

```bash
which node
node --version
```

预期：

```text
/opt/homebrew/opt/node@20/bin/node
v20.x.x
```

### 临时绕过

直接在系统终端构建安装：

```bash
cd /Users/spur/X/space/claudeV2/app_front/app_yanqiang_voice/android
export PATH="/opt/homebrew/opt/node@20/bin:$PATH"
./gradlew :app:installDebug
```

## 2. ColorOS 无法抓取完整蓝牙 HCI 日志

### 现象

Bug Report 中的 `BT_HCI_*.cfa` 只有 16 字节，仅包含空的 `btsnoop` 文件头。

```bash
adb shell getprop persist.bluetooth.btsnooplogmode
# 空

adb shell setprop persist.bluetooth.btsnooplogmode full
# Failed to set property
```

### 原因

ColorOS 限制普通 ADB 开启完整 HCI 抓包；厂商 Release SDK 也没有输出 BLE 原始载荷。

### 替代方案

使用 Nordic 官方 `nRF52840 Dongle（PCA10059）` 作为独立 BLE Sniffer：

```text
戒指 ↔ 手机 App
      ↑
nRF52840 监听空中 BLE 数据包
```

该方案不依赖手机开放 HCI，也不要求戒指使用 Nordic 芯片。戒指使用 Apollo 3 芯片不影响标准 BLE 空中抓包。

注意：只有戒指确实通过 BLE 发送双击、长按或松开事件，Sniffer 才能捕获；如果手势只在戒指固件内部消费，抓包仍只会看到录音工作状态。

### Mac 所需软件

1. Wireshark：查看和分析数据包；
2. Nordic nRF Util：刷入 Sniffer 固件并安装 Wireshark 抓包插件。

手机不需要安装额外 App，继续使用 `app_yanqiang_voice`。

抓包必须在戒指连接 App 之前启动，以捕获连接过程并跟踪 BLE 跳频。

- https://www.nordicsemi.com/Products/Development-tools/nRF-Sniffer-for-Bluetooth-LE
- https://www.nordicsemi.com/Products/Development-tools/nRF-Util
- https://www.wireshark.org/download.html
