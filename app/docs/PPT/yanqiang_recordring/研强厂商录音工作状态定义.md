# 研强厂商录音工作状态定义

## 状态定义

| 状态值 | 厂商定义 | App 行为 |
|---:|---|---|
| `1` | 空闲 | 可以录音，也可以查询或同步已有录音 |
| `2` | 录音中 | 禁止同步，等待录音结束 |
| `3` | 暂停 | 禁止同步，等待录音继续或结束 |
| `4` | 有录音数据待上传 | 文件已经可以同步，App 应立即允许用户发起同步 |
| `5` | 数据上传中 | 禁止重复同步，等待当前传输完成 |

## 正常录音同步流程

```text
1 空闲
→ 2 录音中
→ 4 有录音数据待上传
→ App 发起同步
→ 5 数据上传中
→ 1 空闲
```

## 关键说明

`state=4` 不是“录音收尾中”，也不需要等待它自动变成 `state=1`。

它表示录音数据已经准备好，正在等待 App 发起上传。此时应允许调用：

```java
ServiceSdkCommandV2.INSTANCE.getVoiceRecordFile(false, callback);
```

App 同步门禁规则：

```text
允许同步：state=1、state=4
禁止同步：state=2、state=3、state=5
```

如果在 `state=4` 时等待 `state=1` 才同步，可能形成死锁：戒指等待 App 上传，而 App 又等待戒指变为空闲。
