# Agent Flow 页：Process 与卡片详情「文档」块 UI 设计

> 目的：把已确认的 **Agent Flow 界面与行为** 写死，避免后续为 PDF 去改瀑布流 / Process。  
> 页面叫法见 [APP画面地图.md](./APP画面地图.md)。  
> 记录：2026-08-28（Process 已能通过；文档块按本设计接在详情里）。

---

## 0. 必须先成立的顺序

瀑布流里**每一张短录音卡片**都要先 **Process 成功**，再谈详情里的 PDF/PPT。

```text
短语音进 Agent Flow 瀑布流
        │
        ▼
   点「处理 / Process」     ← 只做转写 + AI 文字/图
        │ 成功
        ▼
   点卡片进入「卡片详情」（同页内，不是新 Stack）
        │
        ▼
   用户要用 PDF/PPT 时，才在详情底部出现「文档」块
```

- **「Agent Flow 处理失败」** = 瀑布流卡片的 Process 失败（`POST /api/audio-task`，`taskType=agent_command`）。  
- Process **不得** 被办公网关、PDF 下载、文档块轨迹拖成失败。  
- 设备页「云端文档」、Safari、`127.0.0.1` **不是** 这条主路径。

---

## 1. 在哪一屏发生

只发生在 **Agent Flow 页**（底部右 Tab「AI Assistant」）。

- 短语音（&lt;30 秒）进瀑布流。  
- 点卡片：还在 **同一层详情**（上方可滚，右下角天蓝悬浮球仍在）。  
- **不新开 Stack**，不跳到 Recordings / 蓝牙 / 云端文档调试页。

自上而下：

1. **‹ 返回 Agent Flow**  
2. **标题卡**：分类、标题、时长  
3. **AI 结果**：文字 / 图（现有）  
4. **转写**：有才显示（现有）  
5. **文档**（第三块同款圆角白卡，紧挨转写下面）— 没有文档任务时 **整块不出现**  
6. 右下角 **天蓝悬浮球** 浮在这层上，不占这一列

```text
┌─────────────────────────────────┐
│ ‹ 返回 Agent Flow               │
│ ┌─────────────────────────────┐ │
│ │ 分类  标题  时长             │ │
│ └─────────────────────────────┘ │
│ ┌─────────────────────────────┐ │
│ │ AI 结果                     │ │
│ │ （字 / 图）                  │ │
│ └─────────────────────────────┘ │
│ ┌─────────────────────────────┐ │
│ │ 转写                        │ │
│ └─────────────────────────────┘ │
│ ┌─────────────────────────────┐ │
│ │ 文档  ← 仅有任务时出现       │ │
│ │ 轨迹…                       │ │
│ │ [PDF 正在生成]  [取消]      │ │
│ └─────────────────────────────┘ │
│                           (●)   │  ← 天蓝悬浮球
└─────────────────────────────────┘
```

## 2. 瀑布流（未进详情）

- 卡片上仍是：分类、标题、摘要/状态、播放、收藏、删除、**处理**。  
- Process 中：按钮不可点，文案「处理中…」。  
- Process 失败：文案「处理失败，点击重试」（中文包）/ `Processing failed · Tap retry`。  
- 有文档任务时，卡片上可有很小的 `PDF` / `PPT` /「生成中」角标；**打开文件只发生在详情**，瀑布流不加第二套大按钮。

---

## 3. 「文档」块三种状态

没有文件、用户也没要求生成时：**整块隐藏**。普通改写、出图，详情与加文档块之前一样。

### 生成中

- 主体是 **轨迹**：一行行往下追加短句（像任务流水，不是再开网页），例如：  
  已听懂：做成 PDF / PPT → 正在写文案… → 正在保存到本机 → 已保存到本机  
- 两个按钮：  

| 按钮 | 作用 |
|------|------|
| **主状态（大）** | 展示「PDF 正在生成」或「PPT 正在生成」，不可点，不是再点一次开始 |
| **取消（小）** | 停掉这一次生成 |

- 此时 **没有**「打开本机文件」。  
- 生成未完成时，悬浮球不要再开一轮听写（避免两份文件抢一张卡）。取消后可以再听。

### 成功

- 轨迹可留下。  
- 一行文件名（可长按复制，备用）。  
- 主按钮 **打开本机文件**：在 Spur 内用系统 Quick Look 预览（PDF/PPT，以后 Excel 也走这一套）。点完成回到详情。不进 Safari、不跳到别的 App。  
- 正文仍只在上面的「AI 结果」，文档块不塞大段文章。

### 失败 / 已取消

- 轨迹停在出错或「已取消」那一步。  
- 短错误 + **重试**。不跳走。  
- 可再从悬浮窗发起。

---

## 4. 悬浮窗（天蓝球）

流程不变：点球听写 → 出文字意图 → 勾确认 / 叉取消。

| 意图 | 行为 |
|------|------|
| 普通改写 | 只改「AI 结果」，文档块不变（没有就不出现） |
| 「做成 PDF / PPT」并确认 | **不换卡片、不新开页**。当前详情里文档块出现并进入生成中 + 轨迹。文件只挂在 **当前这张卡** |

取消听写：什么都不生成。

---

## 5. 切走页面：后台继续

生成一旦开始，用户返回瀑布流、切到 Recordings、进 Device，任务仍在进程内继续，直到成功、失败或点取消。

- 回到这张卡片详情：文档块对上最新状态。  
- 取消：停的是这一次任务，不是杀 App。  
- **杀掉 App**：进行中的生成会中断，下次同步把卡住的「生成中」标失败，需重试。

---

## 6. 明确不做

- 不为这次生成再新建一张无关瀑布流卡片。  
- 不把用户送到设备页 Cloud Office 或浏览器。  
- 不在详情白卡里嵌阅读器；点「打开本机文件」用系统 Quick Look 盖在 Spur 上，点完成回到详情。  
- 不改底部 Tab、不改 Recordings 长录音纪要、不改蓝牙/同步。  
- **不为 PDF 去改 Process 按钮或「必须先 Process」这条主路径。**

---

## 7. 和云端的对应（给排障，不是 UI）

| 用户动作 | 接口 | 成败写在哪 |
|----------|------|------------|
| 瀑布流 Process | `POST https://api.hispurring.com/api/audio-task` | 卡片 `status`：pending → processing → completed / failed |
| 做成 PDF/PPT | `POST …/api/office`，文件 `GET …/office-files/…` | 仅 `card.office`（文档块） |

手机不直连 LLM。音频链路：火山 ASR → 云端 Chat（及按意图生图）。办公链路：网关起草 + 无头 Chrome 出可打开的中文 PDF。

2026-08-28 全卡片 Process 失败、办公 JSON 却还能过：Nginx 工作进程写不了 `/var/lib/nginx/tmp/client_body`（当时 `/` 为 `drw-------`）。带录音的 multipart 被挡，界面只显示 Processing failed。已把 `/` 恢复为 `755`。**不要为这类问题改 Agent Flow UI。**
