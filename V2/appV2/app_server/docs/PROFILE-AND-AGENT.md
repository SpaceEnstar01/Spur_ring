# 首次使用资料与 Agent 边界

当前采用无账号体验，邮箱仅作为用户填写的本机资料，不代表验证过的邮箱或登录身份。

## 当前实现

- APP：本机持久化称呼、内置头像标识、氛围样式、可选邮箱及引导完成状态。仅保存成功后进入；可在设置编辑。不随 AI 请求附带这些字段，不发送验证/营销邮件，不读通讯录或日历。未提供跨设备恢复能力。
- 系统权限：麦克风、Apple Speech、蓝牙由 APP 使用系统接口，在用户明确点击后申请和读取实际授权状态。权限令牌及授权结果不应移到 Java 冒充系统授权。
- Java：模型密钥、服务商调用、限额/并发保护、SSE 超时/保活继续由服务端管理。`AgentInstructions` 统一管理普通/流式回复的系统规则；录音分析需要区分事实与推测，给出建议和待确认问题，不声称执行外部操作。
- 现有 `/api/chat` 与 `/api/chat/stream` 请求协议保持不变，兼容旧 APP。不新增部署路由，也不创建保存邮箱的匿名接口。代码修改需要构建并部署新镜像才会改变线上系统规则。

## 后续适合放到服务端的内容

- 在接入真正身份验证后：用户资料、邮箱验证状态、跨设备设置与记忆同步。用服务端认证后的 subject 识别用户，不用邮箱或客户端传来的 userId 作为授权依据。
- 资料服务需有本人读取/更新/删除权限、数据留存策略、传输和存储保护、数据库备份与持久化卷，避免 Pod 重启丢失数据。此前不能把“设备 ID + 邮箱”视为登录。
- 邮箱验证码登录需独立配置邮件服务，增加验证码过期/尝试限制、重放保护、发送频控、登录会话与退出/注销。禁止先用公开接口积累邮箱再补授权。
- 动态头像目录和引导运营文案在需要远程更新时可以迁到公共配置接口；当前只有六个静态矢量头像，保留本地可以离线使用，无须新增公共路由。
- 原始音频、本机 Speech 转写、系统权限继续留在设备。录音转写文字仅在用户明确开启自动分析或主动请求分析后发送。

内置头像代码为项目内矢量绘制，无外部图片下载、相册访问或服务端上传。
