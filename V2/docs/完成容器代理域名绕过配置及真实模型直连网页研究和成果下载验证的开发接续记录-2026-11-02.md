## 一、为什么需要调整容器代理模式

修改前，Docker Desktop 自身的代理模式为 `system`，容器代理模式为 `same-as-host-proxy`，透明处理容器的 80/443 流量。当前系统 HTTP/HTTPS 代理均为 `127.0.0.1:7897`。

前一轮已证明：Mac 直接访问硅基流动正常，显式经过该代理时 TLS 失败；容器经临时直连路径可以执行真实任务，默认路径失败。

核对本机 Docker Desktop 4.97.0 的实际设置定义后，确认容器域名绕过字段只在 `manual` 模式显示生效。因此采用手动容器代理，填写与系统当前相同的代理地址，复制保留原有系统绕过项，仅增加目标 API 域名。

操作前确认无运行中的容器。使用 Docker Desktop 本机设置接口保存配置，并比对修改前后设置，确认只变化上述四个字段；设置已由 Docker 持久化。重启检查返回 false，未执行 Docker 重启。

**维护注意：容器代理现在固定为当前的 7897 地址，不再自动跟随系统代理地址变化；未来 VPN 软件更换端口时，需同步调整 Docker 容器代理。** 不要将这个 Mac 本机地址写入镜像或 ACK 配置。
