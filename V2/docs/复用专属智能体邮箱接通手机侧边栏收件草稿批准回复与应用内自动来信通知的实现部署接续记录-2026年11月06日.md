# 复用专属 Agent 邮箱，接通手机收件、草稿批准回复与 App 内自动通知

日期：2026年11月06日（Asia/Shanghai）。当前为本地实现与部署准备记录；真实邮箱为用户原有 `spur01@agentmail.to`，已从历史记录和本地配置核对。无密钥写入本文。

## 用户确认的范围

- 复用已有 AgentMail 邮箱与历史 Demo，不新建邮箱、不进行多人自动分配。
- 侧边栏在“新建笔记”下方新增“Agent 邮箱”，显示实际未读数。
- 云端接收新来信并自动总结；App 打开时自动同步铃铛与重要邮件卡，点击进入原信。
- 可编辑回复草稿，审阅收件人/主题/正文后批准发送，未批准绝不发送。
- 本轮不接 iOS 系统推送。App 关闭时云端仍可轮询，重开 App 后补同步。
- 实际发送留给用户在手机中对指定测试对象明确批准；本轮未读取真实邮件、未发信、未自动回复历史合作邮件。

## 实现选择与限制

为当前单用户 Demo 采用云端每60秒轮询、App 前台每20秒同步，不需要新增公开 Webhook 路由、域名或 Caddy 例外。不是实时 Webhook 方案，也不是 APNs。

启用时先把最多50封近期来信作为历史基线，不触发摘要、不生成历史通知；之后新出现的邮件进入未读通知和自动摘要。摘要仅处理邮件为外部不可信资料，研究工具禁用、不刷新开发者 YouTube 授权、没有发信能力。单轮最多处理2封摘要，失败最多3次并退避；存储损坏时停止处理而不静默覆盖。

来信量超过50封且这一轮没有遇到已知邮件时，API标记 backlog，App 提示同步窗口限制。该Demo不是高吞吐全量同步系统；超大量积压、分页补齐、邮件到达实时性和多用户权限须另行完善。

新来信元数据、摘要、未读状态写入正式运行卷，原子替换、文件0600；重启保留去重与已读。重要性由模型分类，不应当作可靠截止日期或承诺的最终判断。通知不自动生成已批准草稿。

## 修改/新增位置（相对 /Users/x/X/space/spur）

- `V2/web/email/notifications.mjs`：持久轮询、历史基线、去重、有限重试与未读。
- `V2/web/server.mjs`：通知API、隔离摘要执行、按启用标记启动/停止worker。
- `V2/appV2/app_mobile/src/services/mailNotifications.ts`：内存通知状态与服务端已读同步，不在AsyncStorage落地邮件。
- `src/components/MailNotificationSync.tsx`：前台自动同步、后台暂停、回前台恢复、服务地址改变时清空旧展示。
- `src/screens/AgentMailboxScreen.tsx`：独立邮箱页面、通知摘要与原有真实收件/草稿面板。
- `src/components/AgentMailboxPanel.tsx`：支持独立页面默认展开、由通知定位原邮件、读后更新通知；保留版本绑定审批和发送状态不明时禁止自动重试。
- `src/components/MailActivitySummary.tsx`：Workspace 只展示真实、未读且需处理的摘要。
- `src/components/Sidebar.tsx`、`AgentDashboard.tsx`、`src/adaptive/ChatWorkspaceHome.tsx`、`src/screens/HomeScreen.tsx`、`src/navigation/types.ts`、`App.tsx`：入口、导航、铃铛与生命周期接入。

- POST `/email/notifications/{编码邮件ID}/read`：持久化已读。
- 原有 `/status`、`/messages`、`/analyze`、`/drafts`、版本批准与`/reply`流程保留。
- 云端需配置 AGENTMAIL_API_KEY、AGENTMAIL_INBOX_ID=spur01@agentmail.to、SPUR_AGENTMAIL_AUTOSUMMARY=1。
- API Key 不交给 App；邮箱仍是单用户个人测试，不把共享 ECS Bearer 解释为完整多人邮箱隔离。

## 部署与验收顺序

1. 将筛选后的邮件env安全SCP到 /root/spur-agent-upgrade/agentmail.env（不上传整个源配置）；保留 root 私有权限。
2. 备份现有 agent.env，仅合并上面3个字段，保留模型、Bearer、Google、Notion OAuth配置。
3. 新镜像先运行隔离测试容器，**测试时 SPUR_AGENTMAIL_AUTOSUMMARY=0**，避免两份worker处理同一邮箱；检查key/inbox连接状态时不发送邮件。
4. 备份正式运行卷和容器参数，使用原正式卷更新容器，启用单份worker；保留Caddy和原端口。停止任何同邮箱测试worker，确保只有正式worker启用自动摘要。
5. 首次baseline后再发送一封新测试邮件；确认自动未读数、摘要与重要卡，不手动刷新。
6. 安装1042，手机打开邮件、编辑草稿、取消批准一次（不发送），然后仅对指定测试地址批准并发送；核对真实收件。服务商接受与已送达分别表述；状态未知不自动重发。
7. 关闭App后发测试邮件，重新打开验证补同步；不宣称后台系统推送。
