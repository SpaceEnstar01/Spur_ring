## 已核实的链路

当前 Vite 5174 原来把 /api 转发到本机4173；taskApi 已使用 async:true、客户端requestId和202响应，查询原任务避免重复提交。ECS 正式HTTPS域名是 https://api.hispurring.com ，测试容器v3在4189，域名没有证据表明已经切换至v3。用户提供的证据证明v3测试容器的Agent-Reach与MediaCrawler抖音搜索通过，不等同于DSH闭环或正式切换。

本机现有 siliconflow.env 没有可用 SPUR_CREATOR_AGENT_TOKEN，专用网页令牌文件也不存在；SSH BatchMode 只读探测返回 Permission denied。没有读取或打印任何实际密码、Token、Cookie或完整配置。

## 第一阶段实现

新增 cloud-bridge.mjs，作为 Vite 服务端中间件。未配置时保持原本机代理；本机私有令牌文件存在时，重新启动Vite启用云端。SPUR_WEB_CLOUD=0 可显式恢复本机模式。

- 固定目标 https://api.hispurring.com ，不能从浏览器指定任意上游。
- 只允许本机5174的Host和同源请求，不启用CORS，不把密钥嵌入前端。
- 仅允许异步chat POST、health、tasks、artifacts和video读取；邮件发送、OAuth管理等不在本轮白名单。切云端后邮箱会说明此阶段未接通，不静默落回本机混用数据。
- 令牌放在 ~/.local/share/spur/web-cloud/agent-token，文件必须无组和其他用户权限，服务端才会读取。
- 不转发浏览器传入的Authorization、Cookie或X-Spur-Connection；请求身份是项目负责人的单人开发身份，尚不是公网多用户系统。
- 拦截跨源请求、非白名单路径、路径编码绕过、同步长请求及上游重定向。上游响应流保留内容类型、文件下载头和Range相关头；不会自动重复提交任务。
- 配置标识 /api/web-backend 只返回模式、标签和非敏感来源；页面启动时读取。本地/云端任务历史使用不同localStorage键，顶部显示实际后端标签。
- 云端绝对成果URL转为本机代理URL，保留签名查询串；外部公开来源链接保持原站点。

## 下一步操作

项目负责人在Mac终端执行：

```bash
cd /Users/x/X/space/spur/V2/web
node scripts/connect-ecs.mjs
```

脚本使用SSH提示ECS密码，只从正式容器spur-agent-ecs-smoke读取单个SPUR_CREATOR_AGENT_TOKEN，经格式检查后原子保存到本机私有目录；不会复制agent.env、不会打印令牌、不会修改ECS容器。输出 WEB_ECS_CREDENTIAL_READY 后重启网页开发服务并刷新。

```bash
npm run dev
```

已有5174服务时先在其终端Ctrl+C退出，不能重复启动。随后验证顶栏“硅谷 ECS · 已连接”，真实异步任务202、执行状态、结果、文件预览和追问，不能把代理单元测试当作真实云端成功。
