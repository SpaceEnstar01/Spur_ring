# 本机转写文件末尾处理修复（2026-10-28）

## 现象与证据

eFLY（iPhone 12）录音保存正常，语音识别和麦克风权限开启，但首页提示录音解码失败。V2 使用本机识别，旧工程主要使用云端转写，不能混同验收。

从设备只读取本次测试录音，未上传云端。文件为单声道 16kHz AAC，时长 5.244 秒。使用同一音频准备函数在 Mac 上复现 NSOSStatusErrorDomain/-39（eofErr）。既有原生合成音频测试也失败。

## 修复

`appV2/app_mobile/native-sdk/ios/SpurSpeechAudio.h` 的转换输入回调原先在读到末尾后继续读取，正常 EOF 被当作解码错误。现先检查 framePosition 与 length，读完后显式通知转换器 EndOfStream，并将每次读取容量限制在剩余帧数以内。原始文件不修改，不改变本机识别策略、云端接口或戒指 SDK。

## 验证范围

修复后既有原生测试通过，涵盖 44.1kHz 双声道转换、45 秒分段、完整时长、静音、取消及源文件不变；同一条失败的手机 AAC 录音转换成功，返回有效 CAF 分段且无错误。macOS 音频测试需要允许访问系统音频服务，沙箱内结果不能直接作为解码结论。

签名 Release 编译通过，已覆盖安装到 eFLY 并启动；手机端完整转写仍待用户点击重试验证。未将测试录音纳入仓库。
