# 意图卡片与商业合作示范 · V2 首批实现

## 授权与边界

用户确认：意图分类规则、卡片字段、状态、首批八种真实框架，加完整商业合作 Agent 示范。只修改 V2，不启用 Java 后端，不部署服务器、不推送。录音与转写基线保留；沿用现有 `/api/chat` 文本接口。

## 真实链路

录音转写 → 原有自动分析授权 / 单条手动分析 → 一次云端请求返回可读回复与结构化意图 → 客户端校验 → 本地事项卡片。既有已启用自动分析仍适用；未开启时手动选择捕捉并确认文字共享。没有自动批量发送旧录音或笔记。

新增文件：

- `appV2/app_mobile/src/intent/model.ts`：意图、八框架、状态、来源字段、严格解析与时间校验。
- `src/intent/prompt.ts`：中文结构化解释协议；同句多意图、逐字证据、缺失信息、完整报告/脚本/邮件内容边界。
- `src/intent/store.ts`：独立持久化台账，来源版本、事项版本、历史、标读、置顶、归档、人工纠正、目标选择、采纳修订。
- `src/intent/runtime.ts`：单条文字请求、去重、原文变更与删除后的失效处理、重启中断恢复、文本笔记入口。
- `src/components/IntentWorkspace.tsx`：Needs you / In motion / Latest deliveries / Ideas & decisions、详情、原文、修改分类、补充资料、确认目标、页内时间。

### 分类

idea、decision、commitment、instruction、correction、progress、question、unknown。一条来源可多项。想法不转为任务；决定不等于执行授权；承诺区分 user_owes / other_owes；低置信度与缺关键字段进入澄清。模型不控制执行状态或外部权限。

### 首批八框架

| 框架 | 行为 |
| --- | --- |
| 想法 | 记录、整理、关联来源；不进入待处理提醒 |
| 决定 | 当前方向、历史；人工确认的替代关系 |
| 承诺 | 主体、对象、交付物、原始时间词、截止确认、用户标记完成 |
| 提醒 | Agent 页内事项，用户明确填写本机日期时间；不调度 iOS 通知 |
| 澄清 | 问题与补充输入；新版本准备后审阅采纳 |
| 邮件 | 完整草稿与待确认字段；不发送 |
| 报告/分析 | 完整分节正文、证据与局限、建议、清单；无数据不造图 |
| 脚本/拍摄 | 完整正文、结构、画面/声音、制作清单 |

### 字段

来源 key、原文、来源时间及可信度、音频/笔记引用；事项 ID、内部 matterId、kind/frame、逐字 sourceSpan、标题、摘要、人物与角色、交付方向、原始日期词、用户确认时间与时区、正文/清单/问题/邮件、状态及原因、版本、读过/置顶/归档、目标关联、变更历史。真实结果不使用示范指标，也不自动加载模型提供的远程图片。

matterId 是本机事项关联标识，不代表已接入 Java Matter 服务或全局语义记忆。未自动上传全量历史来猜测项目归属。录音来源原始时间不可信时，界面注明 Library time，不把同步时间作为承诺日期依据。

### 状态与纠错

recorded、needs_clarification、preparing、ready、needs_confirmation、pending、working、waiting、completed、failed、paused、cancelled、superseded。当前真实执行只涉及内部内容准备及用户操作；不能通过状态按钮把草稿变为已发送。

- 标读与完成分离。
- 用户标记完成会注明用户确认，非独立外部验证。
- “稍后”/暂停、取消、归档分别处理。
- 纠错、进度先选择明确目标，再审阅确认；只记录内部状态，不撤回外部操作。
- 明确新方向替代旧决定时保留旧版，新决定进入有效记录。
- 补充输入成为单独原始笔记；带入用户明确选择的原事项上下文，准备完整版本后由用户采纳。
- 原事项在准备期间被修改，旧版本不能覆盖它。
- 重新解释同来源时匹配已有事项身份，保留完成/暂停/取消状态；历史版本不静默覆盖。

### 故障与既有能力

- 非法 JSON、无原文证据、无效分类：保留可读回复和原文，显示重试，不生成猜测卡片，不自动重复请求。
- 转写改动/删除、任务取消后的迟到响应不能覆盖新状态；重启中断需手动重试。
- 台账读取失败阻止覆盖，保存失败明确报错；与原录音存储独立。
- 原有明确系统闹钟仍使用既有本机规则和实际状态，相关控制区恢复可见；混合决定与普通页内提醒不被闹钟回复快捷路径吞掉。未改变系统闹钟授权与原调度实现。
- 未运行或部署两套后端，未复制密钥，未读取真实邮箱。

## 商业合作示范

独立文件 `src/agent/partnershipDemo.ts` 和 `src/components/PartnershipDemo.tsx`。八个虚构品牌，初始三份草稿、一份明确兴趣回复、两份信息不足、一份等待回复、一份待研究匹配。

- Luma Gear：匹配依据、定制邮件、审阅、模拟批准。
- Northline Audio：明确表达进一步讨论，仍无报价/成交；需要博主确认意愿、排期、报价，以及双方确认范围、使用权、排他与付款。
- Everyday Studio：只问价格，先澄清交付数量、平台、时间、使用范围等；不编造报价。
- 另外五个机会用于完整列表、筛选和阶段演示。

包含合作档案、候选依据、来源说明、完整邮件、回复摘要、缺失条件、建议下一步、手动接手、暂缓、拒绝、模拟回复、沟通历史及重置。所有品牌/回复虚构，example.com 是显示占位地址，不执行实际联络。示范状态与真实台账隔离；Connect Apps 的 Added 不构成授权。

## 验证与限制

- Lint、TypeScript 与 28 套 / 201 项 Jest 测试通过（在最终安装前复核结果）。新增测试覆盖多意图、想法不提醒、缺失信息、收件人、人物与交付物证据校验、时间校验、来源失效、旧编辑拒绝、重新分类保留完成状态、确认目标、修订采纳、决定替换、模拟商业合作无真实发送。
- 使用一条虚构文本调用一次真实 `/api/chat`，HTTP 200，结构校验通过，返回决定、提醒、承诺三项；未上传真实用户资料。模型合并了同主题前置想法，之后加强了逐句保留要求；分类准确率尚未做黄金集评估，不能称为全场景可靠。
- 签名 Release 编译通过，最终版已覆盖安装至 eFLY 并启动，首页截图确认 Organize captured intentions 入口及旧记录正常显示；实际新录音的完整分类与卡片操作仍待用户真机验收。自动测试与接口成功不等于所有意图真机验收。

### 手机验收建议

1. 录音说“我觉得 AI 眼镜值得拍”：本机转写成功后，开启自动分析则生成想法记录；不应出现在 Needs you，也不创建系统提醒。
2. 录音说“决定下期拍 AI 眼镜，提醒我明天写脚本”：应拆分决定和提醒；提醒需用户确认具体日期时间，仅在页内展示。
3. 录音说“我答应摄影师周五给脚本”：检查承诺主体、交付方向、交付物和时间词，手动确认时间后测试完成、暂停和历史。
4. 打开报告/脚本卡补充条件，审阅新版本后采纳；原卡保留历史。准备期间修改原卡，新版本不得直接覆盖。
5. 纠错或进度录音选择正确目标，先看变更预览再应用；取消只改内部状态，不撤回实际外部操作。
6. 商业合作卡测试 Luma Gear 模拟批准、Northline Audio 人工接手、Everyday Studio 信息澄清；真实邮箱、报价和外部发送均不发生。
