这份说明来自 ChatGPT 分享「专门做 UI 设计」。它从商业计划里的界面草图，走到 App 信息架构，再走到一套随任务阶段变化的自适应界面，并单独讨论了创作者网页或 Mac 工作台。它记录的是设计方向和给实现用的说明，不是已经上线的最终视觉验收。

界面要服务的主线是：戒指采集语音，Agent 理解意图并成为中枢，再进入创作者工作流，调用已连接的工具，最后交出成果。个人记忆和持续学习横在整条链路下面。新的决定、项目进展、协作关系和执行反馈会更新个人上下文，让后续行动跟得上用户最新的话。图里的语音是戒指的主要输入。图像、地点、时间和人物被标成手机或外部上下文，不表示戒指本身具备这些传感器。

页面梳理时，用户要求把功能讲清楚，而不是堆导航。记忆页要更丰满，并增加一页来展示打通的几类工具。想法到脚本是这个场景的重要技能，应作为独立一页出现。连接页要让人一眼看到 Spur 专有的外部连接，例如 Gmail 已添加、Notion、Wideframe。信息流页面则按时间往下排：先是旅行视频数据分析卡片，有标题、简短结论和查看入口；接着是爆款视频脚本与框架分析；再接着是一封待确认的跟进，问摄影师 Jack 材料何时发来。用户明确说，现有界面没有底部的 Home、Projects、Me，生成图时要把这三条去掉。先出界面，再放进商业计划，不要把投资人页和产品界面混成一张。

网页或 Mac 端是另一条入口，不替换手机。目标用户仍是自媒体变现博主。他们除了在 App 里操作，也可以在网页对话里直接问旅行博主的流行数据分析，后台调用对应数据。工作台把对话、视频数据、近期项目、Agent 主动更新、待办日程和已连接工具放在同一页，围绕创作者的业务，而不是做成通用聊天网站。

自适应界面的核心判断是：不要用同一种大卡片装所有事情，界面跟着任务阶段变。同一件事从捕捉、执行、需要授权或选择，到完成，外观可以完全不同。内部展示页用来看全部形态；Today 预览才是首页组合，不能把十几种组件机械堆满。建议先做成演示，不要立刻替换现有 Agent Workspace，等手机上看完再决定哪些进入正式首页。产品内示例文案以英文为主，风格保持极简。

前十二种覆盖日常信息密度。一句通知只留「脚本已好」和查看入口。行内问题就地选择，不必跳页。今日待办是紧凑行，时间靠右。执行中只显示阶段，例如搜索、分析、起草、就绪，不用虚假百分比和整屏工具日志。研究报告用封面、标题、摘要和一条建议，完整正文点开再看。视频数据用小型图表，并标明是示意。邮件草稿先给收件人、摘要和审阅，批准不等于发送。录音转化用录音头、原文节选和步骤时间线，默认不全文，也没有假的播放键。标题方案用横向选择。日程是轻量时间轴，点开事件，不写入真实日历。记忆反馈要区分未确认和已确认，并允许纠正，示例不能写成永久偏好。完成事件用一行，点开才看摘要。

后六种来自两张参考图：一张是执行前授权，一张是完成后的结果凭证。行动授权适合发信、发布、改日程和付费。用户只判断允不允许，不读执行日志。信息要写清对象和动作，按钮是拒绝和允许。成果凭证要把完成状态做成可辨认的结果：脚本像文稿，订单像票据，分析像图表，研究像封面，而不是一个 Completed 标签。视觉决策用于封面和主题对比。生成物用于演示文稿、文档和计划，提供预览和修改。前后对比保留原版和改写，用于钩子、邮件和标题。下一步建议在当前任务结束后提出最自然的一项，例如把研究变成大纲，用户可以选择现在不做。

这套界面和二次确认直接相关。分享反对的是每次改意图都要打开 App、找到项目、重说上下文。它同时反对把批准画成已经发送成功。外部动作停在授权面板，允许之后才进入执行，成功必须由结果事件决定，并用另一张界面呈现。授权是用户决定，成果是执行凭证，两者不能合成一步。

实现约束也写进了说明：展示页和真实首页分开；示例不调用真实邮件、发布或日历；复杂报告默认折叠；按钮和状态必须有反馈；小屏不能横向溢出。组件数量不是目标，任务生命周期驱动界面变化才是。先在手机上看真实组合，再决定正式首页收哪些形态。

页面分工可以再收紧一层。记忆页不是聊天记录堆叠，它要让人看见 Agent 记住了什么、哪些还没确认、用户如何纠正。工具页要列出已经打通的几类能力，让人知道戒指一句话后面接的是哪些外部系统，而不是一个含糊的「已连接」。想法到脚本单独成页，因为这是第一代最清楚的技能：灵感进来，研究补上，方案出去。连接页用真实产品名做示范，Gmail 标成已添加，Notion 和 Wideframe 作为后续连接，避免画成商店式的应用墙。信息流则按「分析结论、脚本框架、待确认的对外动作」往下排，让投资人和以后的用户都看得出：Agent 不是只回一段文字。

十二种日常形态各自有默认状态。通知没有边框，点查看才出脚本。行内问题选完就换成反馈，并允许改选。待办勾选和取消都留在原行。执行状态可以手动推进和重播，只为演示阶段，不假装后台一直在跑。研究报告在展开前只给封面和一条方向建议，并提示先选定方向再生成脚本。图表上的日期和点可以点出数值，同时写明指标是示意数据。邮件先短预览，完整草稿要点开，能编辑、保存、取消和批准，但批准不发出。录音默认节选，步骤逐项展开。横向选择要显示当前项。日程点开不写进系统日历。记忆更新把「Agent 推断」和「用户确认」分成两种状态。完成事件展开后仍是摘要，不把历史结果永远摊在首页。

授权卡和成果卡的结构也定过。授权卡上面是准备发送和场景名，中间是一句话说明、收件人和动作，下面两个等宽按钮，草稿入口默认折叠。成果卡上面是完成标题和项目名，中间是版本和状态，下面整行是查看脚本，正文默认折叠。参考图里的大插画可以借鉴「一眼知道在处理什么」，但 Spur 这轮更强调信息行和按钮，不把插画当成主体。视觉选择用两列图片，点选后可更改。生成物把文件类型、页数和一句内容说明放在一起，预览和修改同一行，输入框默认关闭。前后对比用切换保留两版，不能改完就丢掉原文。下一步建议接受后只给模拟反馈，拒绝后收起。

网页工作台和手机首页共用同一套任务语言，但布局不同。网页是桌面工作台：左边或上方进入对话，周围是视频数据、近期项目、Agent 更新、日程和已连接工具。用户可以问「这类旅行视频为什么火」，系统调用流行数据分析，而不是让用户自己打开多个查询网站。手机首页则更短，只放此刻要处理的组合：一句通知、一个待确认动作、一段执行阶段、一份成果、一条完成记录和下一步。两边都不要底部三栏。示例区可以完整展开给内部看，真实事项优先，示例不能写入录音库或任务台账。

给实现的边界也写清楚了。先做内部展示页和 Today 组合预览，文案用英文，交互状态、点击后变成什么、哪些默认折叠，都要按说明做，避免实现时自由发挥。看过真机之前，不替换现有工作区。外部发送、发布和付款停在允许或拒绝。允许之后如果要演示成功，必须是另一次结果事件，并说明这是模拟。这样界面既服务「说完就推进」，也把二次确认留在真正对外的那一步。分享里的界面探索到十八种形态为止；后来工程里补到二十种，是后续实现，不是这份分享已经写完的范围。
